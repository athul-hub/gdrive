# Kapture Stories — Automatic Google Drive Gallery

## Files
- `index.html`: homepage that discovers collection folders.
- `collection.html`: one reusable page for every collection.
- `style.css`: responsive design and mobile hamburger menu.
- `config.js`: main Google Drive folder ID and API key.
- `index.js`: finds child folders and creates collection cards.
- `collection.js`: loads photos/videos, viewer, and Share Collection button.
- `navigation.js`: responsive menu behavior.

## Setup
1. Create a main Google Drive folder, for example `Kapture Stories`.
2. Put each collection folder inside it; put photos/videos inside those folders.
3. For this static public-gallery version, set the parent folder and contents to **Anyone with the link — Viewer**.
4. Enable Google Drive API in Google Cloud Console and create an API key.
5. Restrict the API key to Google Drive API and your hosted website's HTTP referrers.
6. `config.js` is prefilled with the parent folder ID and API key you supplied. If you rotate the key, update it there.
7. Upload all files together to your static web host.

New folders appear after refreshing the homepage. New media appears after refreshing the relevant collection page.

## Privacy
This is a public static gallery design, not a private client gallery. API keys in browser code are visible to visitors, so restrict them. For private galleries, use a backend and proper authentication. Google Drive API permissions and browser video playback may affect individual files.


## Troubleshooting
- `config.js` must be uploaded in the same directory as `index.html` and `collection.html`.
- `index.html` loads `config.js` before `index.js`; `collection.html` loads it before `collection.js`.
- After uploading, hard-refresh with Ctrl+Shift+R or clear the site cache.
- If the API returns 403, check that Google Drive API is enabled and that the API key restrictions allow this website.
- If the API returns an empty folder list, confirm the configured parent folder contains collection folders directly and is shared for public viewing.

## API key safety
The API key is included in browser-side JavaScript and is visible to visitors. Restrict it in Google Cloud Console to the Google Drive API and the exact HTTP referrers for your website. Since the key was shared in a chat, consider rotating it and replacing the value in `config.js`.


## Photo and video viewer fixes
- The lightbox now requests the original image instead of reusing the thumbnail, and scales it to fit the available screen while preserving aspect ratio.
- Videos use Google Drive's embedded preview player, which supports Drive-hosted playback more reliably than a direct download URL.
- For embedded videos to play, the video file itself must be accessible to viewers (for a public gallery, set it to **Anyone with the link — Viewer**). Some videos may take a moment to process in Drive before playback is available.
- If a photo cannot be served by the original-file endpoint, the viewer falls back to a larger Drive thumbnail. Google Drive may still restrict some formats or very large files.


## Collection thumbnail improvements
- Homepage collection cards appear as soon as folder names are fetched; the page no longer waits for every cover thumbnail.
- Cover thumbnails load in parallel, using Drive's `thumbnailLink` where available and a larger thumbnail size as fallback.
- Thumbnail sharpness is limited by the image preview generated by Google Drive. For best results, use a high-resolution representative photo as the first image in each collection folder. The full-resolution photo viewer remains separate from the grid thumbnail.


## More reliable image thumbnails
This version no longer prioritizes the potentially short-lived `thumbnailLink` returned by the Drive API. It uses the stable Drive thumbnail URL first and has two fallbacks if an image fails. All images still need to be viewable by the intended website visitors. Google Drive may limit preview resolution for some files; if originals remain blurry after this fix, the next step is to use a dedicated image CDN or your own thumbnail generation/storage rather than relying on Drive previews.


## Video thumbnails
- Collection cards and the homepage can now use a Google Drive-generated thumbnail for video files. The collection grid shows a play badge over the thumbnail.
- Drive only generates thumbnails for supported videos after processing; if the thumbnail is blank, confirm the video has finished processing in Drive and is shared with the intended viewers.
- If Drive does not generate a poster for a video, upload a representative JPG image alongside the video. For a custom poster, the site would need to associate that JPG with the video.
